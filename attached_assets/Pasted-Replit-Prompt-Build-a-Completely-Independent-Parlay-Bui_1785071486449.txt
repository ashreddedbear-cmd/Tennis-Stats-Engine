Replit Prompt — Build a Completely Independent Parlay Builder

The Parlay Builder is NOT part of the Tennis Matrix AI prediction engine. It is a completely separate application module with its own scoring system, validation logic, configuration, and decision-making process. It must never modify, retrain, recalibrate, or influence the prediction engine.

⸻

Architecture

Create two independent systems.

System 1

Prediction Engine

* Produces match predictions.
* Calculates win probability.
* Calculates recommendation.
* Calculates upset risk.
* Calculates confidence.
* Runs Monte Carlo.
* Stores prediction history.
* Remains completely untouched.

System 2

Parlay Builder

* Reads predictions produced by the engine.
* Never changes engine outputs.
* Performs its own independent analysis.
* Decides which legs should remain or be removed.
* Generates its own scores.
* Has its own database tables if needed.
* Can be improved without affecting the prediction engine.

There must be zero coupling between these systems.

⸻

Purpose

The Parlay Builder exists for one purpose:

Reduce losing legs before a bet is placed.

It should function like a quality-control inspector.

The engine predicts.

The Parlay Builder judges the prediction.

⸻

Workflow

1. Upload screenshots.
2. OCR extracts every match.
3. Match players to the database.
4. Load the engine prediction.
5. Run the Parlay Builder Validation.
6. Score every leg independently.
7. Remove weak legs.
8. Present only the strongest combinations.

Critical Rule

The Prediction Engine and the Parlay Builder must remain permanently independent.

The Prediction Engine predicts outcomes.

The Parlay Builder evaluates whether those predictions are suitable for inclusion in a parlay.

Neither system may modify, retrain, recalibrate, or overwrite the other. Communication must be one-way only: the Parlay Builder may read prediction outputs but must never write back to the prediction engine or influence future predictions. This ensures that improvements to the Parlay Builder never change the core prediction model, and improvements to the prediction model never automatically change the Parlay Builder’s validation logic.
