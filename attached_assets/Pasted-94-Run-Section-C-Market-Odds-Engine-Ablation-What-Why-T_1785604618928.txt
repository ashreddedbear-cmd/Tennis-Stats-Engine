94 - Run Section C – Market-Odds Engine Ablation

What & Why

Tasks #83 and #86 are both Archived. This task re-scopes the remaining work: run auditMarketConsensusAblation.ts to completion so Section C prints, apply the decision rule, and update persistent memory with the result.

Section C re-runs the full prediction engine on up to 5,932 historical rows (tennis-data.co.uk walk-forward, graded, has avgWinner/avgLoser) — once with market odds active and once without — so we know how much of the market's standalone +3.7pp edge (fast direction audit) survives when odds are fed through the engine as one module among many.

Done looks like

Section C has printed: with-odds accuracy, without-odds accuracy, Δaccuracy, Δlog-loss, and a paired sample count ≥ 500.
The comparison to the fast direction audit (+3.7pp) is documented: what fraction of the market's edge carries through when it is one engine input vs. a standalone signal.
Decision rule applied:
Δacc ≥ +0.5pp at n≥500 → market odds module is net-positive in the engine; no weight-tuning needed (document as KEEP).
Δacc < +0.5pp or negative → document as a real module finding (weight-tuning or exclusion may be warranted, document as INVESTIGATE).
.agents/memory/market-odds-ablation-results.md updated with Section C results, the comparison narrative, and the decision reached.
A summary is printed to the task output: with/without accuracy, Δacc, Δlog-loss, the +3.7pp comparison, and which branch of the decision rule applied.
Out of scope

Any changes to engine weights or module code.
Re-running Sections A or B (already complete).
Restarting the API server (must not happen during the run).
