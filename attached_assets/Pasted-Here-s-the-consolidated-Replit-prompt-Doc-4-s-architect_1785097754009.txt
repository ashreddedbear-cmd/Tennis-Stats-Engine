**Non-negotiable separation rule (read first):**
Parlay Builder and Prediction Engine are two independent products sharing only two neutral utility tables: `canonical_players` and `canonical_tournaments`. Parlay Builder must never import from, call, or read: `prediction_results`, `prediction_batches`, `prediction_history`, `prediction_calibration`, `prediction_cards`, or any validation/risk/grade/agreement field. If Prediction Engine is deleted entirely, Parlay Builder must still run. Add a lint/CI check that fails the build if any file under `/parlay-builder` imports anything from `/prediction-engine`.

```

**2. Provider adapters** (each independently disable-able, each reports health)
```

  apiSportsAdapter.ts      // event provider #1: fixtures, live scores, rankings

Each adapter implements: `fetchEvents()`, `fetchOdds()`, `healthCheck()`, `lastUpdated()`. No adapter throws on failure — all return `{ data, error, source, timestamp }`.

**3. Historical backfill job (separate from live path)**

Runs on a schedule (e.g. weekly), pulls Sackmann repo + tennis-data.co.uk CSVs, normalizes into `parlay_historical_matches` and `parlay_historical_odds`. This powers surface-volatility and player-reliability shrinkage calculations — it is never called during a live parlay-building session.

**6. Parlay Builder's own analysis (independent of Prediction Engine)**
Compute from provider data only:
- No-vig probability per player (average across both odds providers, weighted by market freshness)
- Market disagreement / stability score
- Data completeness score (per Doc 4 §5 pattern — did we get stable IDs, surface, recent history, odds from both providers?)
- Player reliability (shrinkage-adjusted, from `parlay_historical_matches`)
