Good instinct to stress-test this before implementing anything — a few things don’t hold up to the same bar the rest of this session was held to.

1. The “narrow/bounded” claim isn’t actually verified — it’s architecturally inferred. Every number in this doc traces to code (apiTennisProvider.ts:671, surfaceElo.ts:113-122, etc.), which is good. But the load-bearing claim — “tier-5 almost never fires for active top-100 players” — has no query behind it. Nobody counted how often tier-5 actually fires in production for top-100 players, or how many top-100 players currently have <5 live-ID rows in historical_matches. That’s the exact thing this session has insisted on everywhere else: don’t accept “should be rare” as a substitute for a real count.

2. There’s a real contradiction with the earlier #51 close-out. The original “low impact” framing said “live API covers the last 3+ years for active players.” This investigation now finds API-Tennis only covers 548 days (~18 months) — BSD is the one with the 3-year window. That’s not a rounding difference; it means the original justification for closing #51 was built on a data-range claim that turns out to be wrong for one of the two live providers. Worth naming explicitly rather than letting it slide under the newer, more careful framing.

3. “All three providers down simultaneously” is treated as rare without evidence. No check was run on actual provider uptime/outage overlap history. If MatchStat “throws immediately” (per the earlier table) more often than assumed, or if API-Tennis and BSD have correlated failure modes (same upstream, same network path, etc.), “all three down” could be meaningfully more common than the narrative assumes.
