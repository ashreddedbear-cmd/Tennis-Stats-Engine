Tennis Matrix AI — Model Monitoring Dashboard and User Navigation

Primary Objective

Create a clean, professional Model Monitoring Dashboard for subscribers.

Do not remove the existing Backtesting page. Move the entire Backtesting page into the Admin/Owner section because it contains technical testing and model-development controls.

The Model Monitoring Dashboard should be a subscriber-facing transparency page that allows users to see how the production prediction system is performing without allowing them to run tests, retrain models, modify settings, or access developer controls.

⸻

1. User Navigation

Update the main user navigation so it is simple, clear, and focused only on features subscribers actually need.

Use this navigation order:

1. Home
2. Run Model
3. Prediction History
4. Model Monitoring
5. Account

Remove any remaining references to Build Match from the navigation, page titles, buttons, breadcrumbs, mobile menu, and internal links.

The correct name is now:

Run Model

⸻

Desktop Navigation

On desktop, display the navigation in a clean top navigation bar or left sidebar depending on the existing application layout.

The navigation should include:

Home

Purpose:

Give the user a quick overview of their account and recent activity.

The Home page may show:

* Current subscription plan
* Predictions remaining today, when applicable
* Recent prediction summary
* Latest completed prediction
* Current model status
* Quick link to Run Model
* Quick link to Prediction History
* Important alerts or system notices

Run Model

Purpose:

This is the main prediction workflow.

Users should use this page to:

* Search for a match
* Select players
* Paste one or multiple matchups
* Upload supported match information
* Review matched fixtures
* Run the prediction model
* View the completed prediction card

The navigation label, page heading, browser title, breadcrumbs, and buttons must all use Run Model.

Do not display the old term Build Match anywhere in the user interface.

Prediction History

Purpose:

Show prediction records belonging only to the currently authenticated user.

Each user must only see their own prediction history.

Users should be able to:

* Review previous predictions
* Search their history
* Filter by date
* Filter by tour
* Filter by tournament
* Filter by surface
* Filter by recommendation
* Filter by upset risk
* Filter by result status
* Open a full prediction record
* Copy an eligible prediction summary
* See whether a prediction won, lost, is pending, or was voided

Do not expose another user’s predictions.

Admin and Owner accounts may have separate administrative access to broader prediction records.

Model Monitoring

Purpose:

Give subscribers a clear and trustworthy view of how Tennis Matrix AI is currently performing.

This should be a monitoring and transparency page, not a developer testing page.

Users may view model health and performance information, but they must not be able to:

* Run backtests
* Start walk-forward validation
* Start shadow replay
* Launch paper trading
* Retrain the model
* Run an optimizer
* Change model weights
* Modify thresholds
* Change calibration settings
* Modify configurations
* Delete validation records
* Access raw developer logs
* Trigger background jobs

Account

Purpose:

Allow users to manage their account and subscription.

The Account page may include:

* Profile details
* Current plan
* Billing status
* Subscription management
* Trial status
* Usage limits
* Notification preferences
* Favorite-player alerts
* Security settings
* Sign out

5. Core Performance Summary

Create a section titled:

Performance Summary

Display clear metric cards for:

* Overall prediction accuracy
* Predictions evaluated
* Current log loss
* Current Brier score
* Expected calibration error
* Average confidence
* Accuracy over the last 7 days
* Accuracy over the last 30 days
* Accuracy over the last 90 days

Each metric should include a tooltip or short explanation.

Examples:

Prediction Accuracy

The percentage of graded predictions where the predicted winner won the match.

Log Loss

Measures the quality of predicted probabilities. Lower values are better.

Brier Score

Measures the difference between predicted probabilities and actual outcomes. Lower values are better.

Expected Calibration Error

Measures how closely confidence levels match real-world outcomes. Lower values are better.

Do not label a metric as good or bad without comparing it with a defined target, historical baseline, or monitored range.

18. Transparency and Explanation Panel

Create an informational card titled:

How to Read This Dashboard

Use clear text such as:

This dashboard shows how Tennis Matrix AI is performing across completed predictions. Accuracy alone does not fully measure model quality, so the dashboard also monitors confidence calibration, data quality, uncertainty, model agreement, surface performance, and competition-level performance.

22. Access Control

Use server-side role validation for every protected Admin route and action.

Roles:

* User
* Admin
* Owner

Permissions:

User

May access subscriber pages and only their own private data.

Admin

May access approved administrative pages and management controls.

Owner

May access all application features and administrative controls.

Owner and Admin access must not be granted based only on hidden UI elements, email text displayed in the browser, or client-side state.

Validate permissions on the server.

⸻

23. Empty, Loading, and Error States

Every dashboard section must have proper states.

Loading

Show clean skeleton cards or loading indicators.

Empty

Example:

No graded predictions are available for this monitoring period.

Delayed Data

Example:

Some monitoring information is delayed. The most recent available results are shown.

Error

Example:

This monitoring section is temporarily unavailable. Other areas of the application remain operational.

Do not show raw API errors, SQL errors, stack traces, or private technical information to subscribers.
