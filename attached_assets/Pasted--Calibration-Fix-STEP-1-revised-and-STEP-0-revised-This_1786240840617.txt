# Calibration Fix — STEP -1 (revised) and STEP 0 (revised)

This slots in ahead of the existing spec: STEP -1 runs before anything else, STEP 0 replaces the specialist-only version. STEPs 1–3 are unchanged except for the wiring note at the end.

**Changed in this revision**, after reviewing Pegula/Shnaider and Rinderknech/Nakashima alongside Kostyuk/Swiatek:

- Added **-1e**: across all three matches on file, Specialist-contribution + General-contribution alone reproduce the displayed headline probability exactly. Needs a code-level confirmation of whether raw consensus ever actually feeds the final number.
- Added **-1f**: the Model Conflict narrative text on the Kostyuk screen pairs a sub-50% number with a player it calls "favored" — a contradiction on its face, and a separate code path from the structured Model Votes table.
- Extended **-1c**: General's 99.6% on Pegula/Shnaider (a fully concordant case, no reversal) is a tail-calibration risk the original disagreement-only filter would never catch.
- Extended **0b/0d**: Rinderknech/Nakashima is a live B-concordant case. Worked into the spec below alongside Kostyuk's B-dominant-General, since the proposed ceiling fix breaks against them in opposite ways.

## STEP -1 — Calibration Orientation Audit (run first, before trusting any STEP 0 backtest)

Purpose: rule out a plumbing bug before trusting a backtest built on top of the calibrators. If orientation is wrong, STEP 0's ROI numbers measure the bug, not a strategy.

**-1a. Reference-player convention trace**

Trace the code path from raw signal → calibration input → calibrated output → the "FAVORED" UI label. Document, with file/line references:
- What player convention is the calibrator's *input* expressed relative to (player1-as-stored, model's favorite, home player, etc.)?
- What convention was used when *fitting* each calibrator — same question, for the training pipeline?
- Confirm both match, and confirm the "FAVORED" label is derived from the same convention.

A mismatch between fit-time and inference-time convention is the most likely bug shape, and it would produce exactly this reversal pattern.

**-1b. Swap-invariance test** (automated, no historical data needed — can run today)

For a batch of matches, run the full pipeline twice: once as (player1=A, player2=B), once as (player1=B, player2=A), with the same underlying stats attached to the correct player either way. Assert:
- Predicted winner is identical both ways
- P(A wins) computed one way equals 1 − P(A wins) computed the other way, within tolerance

Run separately for Specialist, General, and the final blend. Report as N/N pass, same style as the existing suite.

**-1c. Isotonic bin inspection (Specialist and General — missing before; extended to tail outputs)**

For both calibrators, identify the exact raw input value used for this match, then find the pooled isotonic segment it falls into. Report, per calibrator:
- Input range of the pooled segment
- Training sample count in that segment
- Actual empirical win rate in that segment (should equal the calibrated output — if it doesn't, the calibrator isn't being invoked or serialized correctly)
- Flag `LOW_SUPPORT` if segment count < 30

This directly answers whether a given calibrated output is backed by real signal or a handful of noisy training points.

*Extension:* run this same check on any calibrated output ≥90% or ≤10%, independent of whether the match is a conflict case. General's output on Pegula/Shnaider was 99.6%, with raw consensus, Specialist, and General all agreeing on the same player — no reversal, so it would never surface under STEP 0's disagreement filter. A near-certain output sitting on a thin edge bin is a stake-sizing risk on a pick that was already going to be made, not just a directional one. Flag `LOW_SUPPORT` the same way.

**-1d. No-leakage check**

Confirm both isotonic calibrators are fit walk-forward (only on matches chronologically before the evaluation point), not fit once on the full corpus. Reuse the walk-forward leakage-audit pattern already established elsewhere in this codebase, extended to cover both calibrators specifically — that's a different code path than what's been audited before.

**-1e. Final-blend attribution check (new)**

Purpose: confirm whether the five raw-consensus signals (Surface Elo, Serve & Return, Recent Form, Head-to-Head, Market Consensus) ever mathematically influence the *final* blended probability once Specialist is Available/Active, or whether the final number is fully determined by Specialist+General alone.

Evidence motivating this — on all three matches on file, (Specialist raw% × Specialist weight) + (General raw% × General weight) reproduces the displayed headline probability exactly, to the rounding shown on-screen:
- Kostyuk/Swiatek: 59.8×.85 + 84.5×.15 = 63.5 → displayed 64%
- Pegula/Shnaider: 91.3×.85 + 99.6×.15 = 92.5 → displayed 93%
- Rinderknech/Nakashima: 85.9×.702 + 84.5×.298 = 85.5 → displayed 86%

Find the actual final-probability formula in code and determine:
- Does the raw-consensus group's own blended value ever enter that formula, or does Specialist+General's blend simply replace it whenever Specialist is Available/Active/Reliable?
- If it's a replace/override: is that intentional (a documented fallback hierarchy), or is there a meta-weight that's supposed to be non-zero and is being computed or applied as zero?

**Gate implication:** if this turns out to be an unintended bug (a meta-weight silently collapsing to zero), fix it before running STEP 0 — the system is currently more reckless than its own design intends. If it's an intentional override, STEP 0 can proceed, but every "disagreement" case in STEP 0 must be narrated as *"does the override disagree with the panel it replaced, and was the override right,"* not as *"how does the ensemble resolve internal conflict"* — those are different claims, and STEP 1's fix options differ depending on which one you're actually looking at.

**-1f. Model Conflict narrative-text audit (new)**

Purpose: the structured Model Votes table and the natural-language "Model Conflict" summary sentence appear to be two separate code paths. Only the table has been checked for orientation so far.

Evidence motivating this — the Model Conflict text on the Kostyuk/Swiatek screen reads: "Surface Elo → Iga Swiatek (26%, weight 0.36)... favored Iga Swiatek." A player can't be "favored" at a 26% win probability — that's a contradiction on its face. The 26% is far more likely Kostyuk's own raw number (the same reference-player convention -1a is checking on the structured table), attached to Swiatek's name by the sentence template instead of being flipped to ~74% or attached to Kostyuk's name instead.

Trace the code that generates this specific sentence (separate from the Model Votes table's rendering code) and confirm it resolves "which player's number goes next to which player's name" using the same, correctly-applied convention as -1a. This doesn't gate STEP 0 — it doesn't touch the actual bet decision — but it's what a human reviewing a case actually reads, so it should be fixed regardless of what -1a–-1e turn up.

---

**Gate:** if -1a, -1b, or -1e (when -1e surfaces an unintended bug rather than a documented override) fails, stop and fix before running STEP 0. If -1c shows `LOW_SUPPORT` for either calibrator's relevant bin — including the extended tail-output check — label STEP 0's results for that calibrator low-confidence regardless of overall sample size. -1f should be fixed on its own timeline; it doesn't block STEP 0.

## STEP 0 (revised) — Stratified backtest across both calibrators

Original gap: only queried cases where raw consensus was unanimous *and Specialist* disagreed. Misses General-only reversals, and doesn't distinguish which calibrator is actually driving the blend when both disagree — which is what happened in the Kostyuk/Swiatek case (Specialist mildly disagreed at 59.8%, General strongly disagreed at 84.5%, the blend followed General).

**0a. Define raw consensus — report both**
- Strict: all 4 of {Elo, Serve/Return, Recent Form, Market Consensus} unanimous
- Loose: ≥3 of 4 agree

(Strict alone will likely be too small a sample; loose gives more power. Report both so small-N caveats stay honest either way.)

**0b. Classify every case where raw consensus disagrees with the calibrated blend**

| Type | Specialist vs. raw consensus | General vs. raw consensus |
|---|---|---|
| S | disagrees | agrees |
| G | agrees | disagrees |
| B | disagrees | disagrees |

Within type B, sub-tag further:
- **B-dominant** — one calibrator sits clearly farther from 50% than the other. B-dominant-Specialist and B-dominant-General are different populations that a single "lower the specialist ceiling" rule affects in opposite ways.
- **B-concordant** — Specialist and General are within ~5pts of each other (both extreme, both wrong direction). Reweighting can't help here almost by construction — see 0d.

This split is the one that matters for STEP 1.

*Worked examples on file* (for calibrating intuition — not a substitute for the full backtest below):
- **Kostyuk/Swiatek** — raw consensus (4/4) → Swiatek. Specialist 59.8% Kostyuk (weight 85%), General 84.5% Kostyuk (weight 15%). Type B, **B-dominant-General** (distance from 50%: Specialist 9.8pts, General 34.5pts — 24.7pt spread).
- **Rinderknech/Nakashima** — raw consensus (4/4) → Nakashima. Specialist 85.9% Rinderknech (weight 70.2%), General 84.5% Rinderknech (weight 29.8%). Type B, **B-concordant** (distance from 50%: Specialist 35.9pts, General 34.5pts — 1.4pt spread).
- **Pegula/Shnaider** — raw consensus (4/4) and both calibrators agree, all on Pegula. Not a conflict case; doesn't classify under this table. General's 99.6% output routes to the extended -1c tail check instead.

**0c. For each type/sub-type, report four separate numbers — don't conflate them**
- **Win rate** — blend's pick win rate
- **Model EV** — calibrated probability × odds available at prediction time − 1 (needs prediction-time odds stored; if only closing odds exist historically, say so explicitly rather than substituting silently)
- **Realized ROI** — actual profit/stake at prediction-time odds
- **Calibration quality** — Brier score, log loss, reliability by probability band, computed per stratum

Separately, also report **CLV** (prediction-time odds vs. closing no-vig odds) as a market-movement check independent of win/loss.

If fewer than ~30 cases exist in a stratum, report it and label that stratum's conclusions directionally suggestive only — same standard as before, applied per-stratum instead of pooled.

**0d. The check that actually tests the STEP 1 fix**

Before applying any specialist-ceiling change, simulate what each stratum's ROI/win-rate would have been under the proposed new ceiling (e.g., capping Specialist's weight at 65%, routing the remainder to General), computed separately for B-dominant-Specialist, B-dominant-General, and B-concordant. Two real cases already show this can't be a single global number:

- **Kostyuk (B-dominant-General):** 59.8%×0.65 + 84.5%×0.35 = 68.4%, vs. the original 63.5% — *more* confident in Kostyuk, not less. The ceiling backfires here because General, not Specialist, is the extreme voice; capping Specialist just hands more relative weight to the more-extreme General.
- **Rinderknech (B-concordant):** 85.9%×0.65 + 84.5%×0.35 = 85.4%, vs. the original 85.5% — functionally unchanged. Specialist and General already agree almost exactly, so reweighting between them can't move the pick back toward raw consensus at all.

A single global ceiling on Specialist's weight is now empirically shown to (a) actively worsen B-dominant-General cases and (b) do nothing for B-concordant cases. It would need to also cap General's influence for the first problem, and needs an entirely different mechanism for the second — either blending back toward raw consensus when both calibrators diverge from it together, or resolving *why* they diverge together in the first place (see -1e/-1f).

---

**Wiring note for STEP 1:** its decision tree should branch on the STEP 0d stratified result *by sub-type* (B-dominant-Specialist / B-dominant-General / B-concordant), not the pooled STEP 0 result and not on B-dominant alone. A ceiling change that's net-positive in aggregate but net-negative for B-dominant-General, or inert for B-concordant, would still ship a fix that makes cases like Kostyuk's and Rinderknech's worse or untouched. It should also treat -1e's finding as a precondition: if raw consensus turns out to be a designed override rather than a blended input, "lower the ceiling" may not even be the right category of fix — the more relevant lever may be *when to trust the override at all*, not how much weight it carries once trusted.
